# Production Bug Tracker

This folder contains documentation for production bugs that have been identified and fixed. Each bug report serves as a learning resource for new developers and a historical record of issues encountered.

## Naming Convention

Bug reports follow this naming pattern:
```
YYYY-MM-DD_SHORT_DESCRIPTION.md
```

Example: `2025-01-27_HIRAGANA_DOTS_ANDROID_CHROME.md`

## Document Structure

Each bug report should include:

1. **Summary** - Brief description of the bug
2. **Symptoms** - What the user experienced
3. **Root Cause** - Technical explanation of why it happened
4. **Investigation Process** - How the bug was diagnosed
5. **Solution** - What was done to fix it
6. **Files Modified** - List of changed files
7. **Prevention & Best Practices** - Lessons learned
8. **User Communication** - How the user was notified (if applicable)
